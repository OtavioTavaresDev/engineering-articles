Identity Malware

The Rise of Infostealers and Session Hijacking

Why modern attackers no longer need passwords to compromise accounts.

May 10, 2026 15 min read

The Infostealer Economy

Infostealers — RedLine, Lumma, Stealc, Raccoon — are the most active malware family of 2026. They operate as a service: affiliates distribute stealers via cracked software, fake updates, or malvertising. The stealers harvest:

  • • Browser cookies (including session tokens for Google, Microsoft, AWS).
  • • Saved passwords from Chrome, Edge, Firefox.
  • • Credit card autofill data.
  • • Crypto wallet files and private keys.
  • • VPN and RDP configurations.

From Stolen Cookies to Full Account Takeover

Attackers don't need to crack passwords. They replay the stolen session cookie directly into their own browser. If the cookie is still valid, they bypass both passwords and MFA. In 2025, the Lapsus$ group famously compromised a major tech company by buying stolen session cookies from an infostealer log marketplace.

🧠 Attack Flow

1. User downloads cracked software → infostealer installed.
2. Stealer exfiltrates `%LocalAppData%\Google\Chrome\User Data\Default\Cookies`.
3. Attacker decrypts cookies (Chromium stores them with a local key).
4. Attacker loads cookies into a fresh Chrome profile and visits `https://outlook.office.com`.
5. Attacker is logged in as the user — no password, no MFA prompt.

Session Token Lifetimes: The Real Problem

Many platforms issue session tokens that remain valid for days or weeks. A stolen token can be used long after the user changed their password. The fix is token binding — tying the token to a specific device fingerprint. But few organizations enforce it.

Detection and Mitigation

✅ Preventative Controls

  • • Enforce FIDO2/WebAuthn hardware keys (resistant to cookie theft).
  • • Disable saved passwords in browsers via GPO/MDM.
  • • Use Application Control (e.g., WDAC) to block unapproved executables.
  • • Deploy endpoint detection (EDR) that monitors for stealers.

🔍 Detection Signals

  • • Login from new IP + same session token as previous login (impossible travel).
  • • User agent mismatch (e.g., session created with Chrome on Windows, reused with Firefox on Linux).
  • • Multiple MFA prompts followed by success (token replay from different device).

Incident Response for Session Hijacking

  1. Terminate all active sessions for the compromised user immediately (Azure AD: `Revoke-AzureADUserAllRefreshToken`).
  2. Reset user's password (even if MFA was bypassed, attacker may have persistent refresh tokens).
  3. Investigate if the attacker accessed any sensitive data or established persistence (e.g., added new MFA methods).
  4. Scan the user's device for infostealer malware (look for known stealer artifacts).
  5. Educate the user about downloading untrusted software.
