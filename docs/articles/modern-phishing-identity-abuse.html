Modern Phishing Attacks and Identity Abuse

Session hijacking, MFA bypass techniques, and the evolution of identity-focused attacks.

May 4, 2026 12 min read

MFA Is Not a Silver Bullet

For years, security teams were told: "just add MFA." But attackers adapted. Modern phishing kits now include reverse proxies that steal session cookies in real time, bypassing both SMS and TOTP. The attack, known as Adversary-in-the-Middle (AiTM), captures the token after MFA validation.

🎣 How AiTM Works

1. User clicks a link to attacker-controlled login page (looks like Microsoft/Google).
2. Page proxies requests to the real login page.
3. User enters credentials and MFA code.
4. Attacker captures the session token and replays it in their own browser.
5. Attacker now has persistent access, even after user changes password.

MFA Fatigue and Push Spam

In 2025, threat actors exploited "MFA fatigue" — repeatedly sending push notifications to a user's authenticator app until they accept out of frustration or confusion. This technique led to the compromise of several high-profile companies, including Uber and Cisco. The fix? Number matching and geographic location checks in MFA prompts.

Session Hijacking Without Credentials

Infostealer malware (like RedLine, Vidar, and Raccoon) has become a primary driver of identity attacks. These steal browser cookies, saved logins, and auto-fill data. Attackers buy the logs on darknet markets and replay the session cookies directly, bypassing both passwords and MFA.

The only mitigation is device posture and continuous authentication — checking that the session's IP, user agent, and device ID match the original login. Solutions like Okta Device Trust or Azure AD Conditional Access can enforce this.

Detection Engineering for Identity Attacks

  • • Impossible travel: Login from New York and 5 minutes later from London → block.
  • • New device enrollment: Alert when a device never seen before registers for MFA.
  • • OAuth app consent grant: Malicious apps requesting high privileges (Mail.Read, Files.ReadWrite) should trigger review.
  • • Multiple MFA failures followed by success: Classic fatigue attack pattern.

Hardening Identity Infrastructure

✅ Recommended

  • • FIDO2/WebAuthn (hardware keys) — resistant to AiTM
  • • Conditional Access with sign-in frequency
  • • Token binding (prevents token replay across devices)
  • • Continuous access evaluation (CAE) in Azure AD / Google
