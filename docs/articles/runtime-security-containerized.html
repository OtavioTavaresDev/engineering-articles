Runtime Security in Containerized Environments

Why image scanning alone is insufficient for modern container security.

May 9, 2026 11 min read

The False Sense of Security from Image Scanning

Most teams believe that scanning container images for CVEs is enough. It's not. Image scanning catches known vulnerabilities in packages — but it misses runtime attacks: cryptominers deployed after compromise, reverse shells, privilege escalation, and container escapes.

A 2026 Sysdig report found that 75% of runtime container attacks exploited misconfigurations, not CVEs. An overly permissive RBAC, a writable hostPath mount, or a privileged container trivially bypasses any image scanner.

Runtime Attack Vectors

🐚 Reverse Shell from Compromised Container

Attacker exploits a vulnerable web app, then calls out to a C2 server. Traditional network firewalls allow egress.

🔓 Privilege Escalation to Host

Container runs as root with `privileged: true` or `CAP_SYS_ADMIN`. Attacker mounts host filesystem or escapes via `nsenter`.

💸 Cryptominer Deployment

Attacker downloads and runs XMRig inside the container, consuming CPU for cryptocurrency mining.

🗄️ Lateral Movement via Service Accounts

Stolen service account token used to access Kubernetes API and launch more pods.

Falco: The Standard for Runtime Detection

Falco (CNCF project) monitors syscalls, Kubernetes audit logs, and container metadata. It detects anomalous behavior like:

  • • Package manager running in a container (`apt`, `yum`).
  • • Shell spawned in a container (e.g., `exec -it /bin/bash`).
  • • Unexpected outbound connections (e.g., to a mining pool).
  • • File writes to sensitive host paths (e.g., `/etc`, `/proc`).
# Falco rule example
- rule: Launch Package Manager in Container
  desc: Detect package manager executed inside a container
  condition: container.id exists and proc.name in (apt, yum, apk)
  output: Package manager run inside container (user=%user.name command=%proc.cmdline)
  priority: WARNING

eBPF for Deep Visibility

eBPF (extended Berkeley Packet Filter) allows running sandboxed programs in the Linux kernel without changing kernel source. Tools like Cilium, Tetragon, and Falco with eBPF drivers provide:

  • • Network flow monitoring (every connection, no sidecars).
  • • Process execution auditing (complete ancestry tree).
  • • File access monitoring (critical for Ransomware detection).

Operationalizing Runtime Security

  1. Deploy Falco as a DaemonSet on your Kubernetes cluster.
  2. Forward Falco events to a SIEM or a lightweight alert system (e.g., Slack webhook).
  3. Start with a baseline profile — learn what "normal" looks like for your workloads.
  4. Create exception rules for known benign behavior (e.g., your CI agent uses apt).
  5. Enable automated response for high-confidence detections (e.g., kill pod, isolate node).
